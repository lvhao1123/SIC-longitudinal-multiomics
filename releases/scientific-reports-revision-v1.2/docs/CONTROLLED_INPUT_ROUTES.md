# Controlled input acquisition and construction

## Access and separation

Apply for OMIX011182 through the National Genomics Data Center: https://ngdc.cncb.ac.cn/omix/release/OMIX011182. Approval governs access and use of individual-level clinical and molecular files. This code package neither grants access nor redistributes those files. Keep inputs and derived patient-level outputs in private directories.

## Clinical annotation

`analysis/build_clinical_annotation.R` takes an approved raw clinical CSV, the matching curated 504-patient Day-1 baseline workbook, and a new private output directory. It removes only the terminal sampling suffix to identify patients, creates D1/D3/D5 annotation rows, and carries Day-1 covariates forward for molecular linkage. These rows are annotations, not proof that a molecular sample exists; the model scripts match actual assay columns and require survival beyond each entry time. A separate output retains raw longitudinal clinical values alongside prefixed baseline values.

```
Rscript --vanilla analysis/build_clinical_annotation.R RAW_CLINICAL_CSV CURATED_BASELINE_XLSX NEW_PRIVATE_DIRECTORY
```

The annotation builder requires the matching curated 504-patient Day-1 baseline workbook as a controlled input. It constructs the longitudinal annotation but does not establish the provenance of every curated value from the original clinical download. The curated workbook is not a public example. Access to an equivalent curated baseline must be confirmed within the authorised data-use arrangement; do not substitute an unverified workbook or assume an unrestricted author-to-researcher handoff.

## Molecular and supporting inputs

- RNA counts: authorised OMIX011182-04 text. The primary RNA script maps Ensembl identifiers with the specified gene map, aggregates symbols, applies initial TMM, CPM filtering, second TMM and logCPM. It creates the controlled expression matrix used by downstream analyses.
- Protein matrix: authorised OMIX011182-05 workbook. Use the corresponding protein QC feature table for the primary filtering rule. The documented computational reconstruction and the CV-dependence comparison do not confirm the input scale or experimental triplet definition. The original QC-table generation provenance remains separate from its reproducible filtering behaviour.
- Gene mapping: the versioned mapping construction script and resulting mapping input are specified by the primary configuration. Changing annotation versions may change features and is not a drop-in reproduction.
- Hallmark: obtain h.all.v2026.1.Hs.symbols.gmt from MSigDB under its terms. The code package does not grant a gene-set redistribution licence.
- Patient availability, pathway scores and RNA/protein matrices: generated by the primary stages and retained privately; see CODE_CHAIN.tsv for consuming stages. They are not replaced by published aggregate tables.
- Aggregate table/figure reproduction: no patient-level access is required; use the supplied aggregate inputs and current table/plot entries.
