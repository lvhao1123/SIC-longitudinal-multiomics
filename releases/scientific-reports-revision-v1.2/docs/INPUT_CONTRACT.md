# Controlled inputs

The primary pipeline requires the longitudinal clinical annotation, raw RNA count text, protein annotation workbook, protein QC feature table, the specified Ensembl-to-symbol map and the specified Hallmark version. Protein-subset selection also uses a patient-level availability table. Revision analyses require the matrices and score tables generated by the relevant primary stages.

The clinical annotation must contain unique SampleName values, PatientID, day_num, sTatus, surv_time, the recorded baseline covariates and recruitment-centre identifiers. The source annotation carries baseline covariates across measurements; it is not identical to an unprocessed OMIX download. Analysis risk sets require follow-up beyond entry at 0, 2 and 4 days.

The clinical annotation-construction script has been located and its path-parameterised version is included as analysis/build_clinical_annotation.R. It reconstructs the annotation from a matching curated Day-1 workbook. The upstream curation of that workbook from the original clinical download is not fully documented by this builder. See CONTROLLED_INPUT_ROUTES.md for the actual build route, controlled prerequisites and remaining source-curation boundary.

The QC table contains UniProt/gene mapping, missingness, converted CV and pass flags consumed by the protein pipeline. Its filtering can be reconstructed, but reconstruction does not establish the matrix scale or the experimental meaning of the QC groups. These assumptions and the CV-dependence analysis are described in the Supplementary Methods and Table S18.

Keep all controlled inputs and derived individual-level outputs outside this repository. Use config examples and environment variables; do not insert local paths or identifiers into public files.
